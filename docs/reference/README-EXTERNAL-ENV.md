# Shared external SSH `.env` — Lab v3

This overlay allows the **single RVV-VLA-Lab repository** to read the existing
`C:\mycode\Simdjson\.env` without copying or renaming it.

Both legacy `CLOUDV_*` keys and the newer `RVVLAB_*` keys are recognized.
Where both are present, nonempty `RVVLAB_*` values take priority. Unknown
variables are ignored; no shell code in the `.env` is executed.

The configuration is discovered in this order:

1. `RVVLAB_ENV_FILE` (explicit environment variable, optional).
2. `.env` in the **parent of the Lab root** (`C:\mycode\Simdjson\.env`).
3. `orchestrator/.env` inside Lab.
4. `studio/.env` inside Lab.

The Studio also respects an existing manually selected `.env` file if it still
exists. Its previous autogenerated internal default is replaced when the
external shared file exists. If the Studio was open during patch installation,
restart it to load these changes.

The Lab does **not** embed SSH host details, passwords or keys in the project,
and it never auto-connects. SSH host fingerprints remain strictly verified; if
the old `.env` lacks a `CLOUDV_HOST_SHA256` / `RVVLAB_HOST_SHA256`, add a verified
fingerprint to the local file before connecting.

To check the configuration shape (no network connection, no secrets printed):

```powershell
$repo = 'C:\mycode\Simdjson\RVV-VLA-Lab'
& "$repo\.venv\Scripts\python.exe" "$repo\tools\check_ssh_env.py"
& "$repo\LAUNCH_RVV_VLA_LAB.bat"
```

Installation: extract this overlay ZIP **into the Lab repository root**. It
contains only scripts and documentation; it contains **no `.env`**.

Note: `python tools/rvvlab.py setup` continues to write only to Lab's
`orchestrator/.env`. If the shared workspace `.env` exists, it still has
precedence. To force a different file in your PowerShell session:

```powershell
$env:RVVLAB_ENV_FILE = 'C:\mycode\Simdjson\RVV-VLA-Lab\orchestrator\.env'
```

This is a configuration compatibility patch, not a native RISC-V performance test.
