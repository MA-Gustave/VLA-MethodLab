# EPCC temporary SSH diagnostic mode

This package is **only** for testing the `gateway.epcc.ed.ac.uk` → `riscv-login.epcc.ed.ac.uk` connection. It must not be used for production data or regular connections.

## Install (Windows, drop root & overwrite)

1. Close RVV-VLA Lab Studio.
2. Unzip `RVV-VLA-Lab_EPCC_TEMP_TEST_MODE_DROP_ROOT.zip` into `C:\mycode\Simdjson\RVV-VLA-Lab\` preserving the `studio/` and `orchestrator/` paths and overwrite the matching files.
3. Download `.env.epcc` separately into `C:\mycode\Simdjson\.env.epcc` (outside the `RVV-VLA-Lab` directory), replacing the previous EPCC test profile only.
4. Restart Studio. Select **EPCC** and the `.env.epcc` path, then connect. Confirm the explicit warning about **unverified SSH host keys**.
5. After diagnostics, set `RVVLAB_INSECURE_EPCC_TEST_MODE=0` and configure valid pinned host keys before any operational use. The Cloud-V profile is unaffected.

## Why this does not resolve the current gateway error

The Windows SSH command already passed the gateway's *first-use host-key prompt* and then received `Connection closed by 129.215.62.104 port 22` **before reaching** `riscv-login`. That is a gateway-authentication/authorization or connection-policy problem, not a SHA256 host-key validation error in Studio. EPCC requires a gateway SSH key and MFA TOTP, and the front-end account may require separate provisioning and password. Studio currently uses a Paramiko SSH tunnel and may not implement this interactive MFA method; a successful Windows OpenSSH connection should be verified first.

Run in PowerShell:

```powershell
ssh -vvv -E "$env:TEMP\epcc-ssh-debug.log" -J gustave@gateway.epcc.ed.ac.uk gustave@riscv-login.epcc.ed.ac.uk
Get-Content "$env:TEMP\epcc-ssh-debug.log" -Tail 50
```

Share only the last diagnostic lines, removing tokens, passwords, private-key content, and any other secrets. Your SAFE account information showed only gateway access; confirm that a `riscv-login` account is also enabled.

## Security and limits

The new `RVVLAB_INSECURE_EPCC_TEST_MODE=1` switch:

* permits missing SHA256 host fingerprints **only** when the gateway is exactly `gateway.epcc.ed.ac.uk` and the target is under `.epcc.ed.ac.uk`;
* uses Paramiko `AutoAddPolicy()` for the two SSH hops **only** after a GUI consent prompt;
* does **not** bypass passwords, SSH-key authentication, MFA, forwarding policy, account provisioning or Slurm;
* does **not** change the normal verified-host policy for other hosts;
* is intended for short, non-sensitive diagnostics only; unauthenticated SSH hosts can allow man-in-the-middle interception.

This is a code-only patch (3 Python files and an offline test); release SHA256 manifests in your existing installation are not regenerated by the ZIP because they depend on the files already present in your working tree. If you maintain a release manifest, recalculate the three modified SHA256 entries locally. This patch has **not** been tested against an actual EPCC account, nor can it make `riscv-login` execute native RISC-V code: the front-end is x86-64 and compute jobs use the EPCC scheduler.
